# Hermes Desktop 截图体验优化提案：目录管理 + 悬浮窗 + 一键清理

> 日期：2026-08-07 ｜ 状态：**已采纳（同日实施，按 §6 决策修订）**
> 前置：`docs/quick-screenshot-proposal.md`（v0.18.8 已落地快速截图）。本提案是三个配套优化：截图存储目录可管理、可选的截图悬浮窗、设置里一键清理截图缓存。
>
> **已拍板的决策（2026-08-07）**：
> 1. 目录：**默认 app-data**；可选切到 `<项目>/.hermes/screenshots/`；"自动加入 git 排除文件"做成**用户可勾选的选项**（默认不自动写，勾选后幂等写 `.git/info/exclude`，不碰 `.gitignore`）。
> 2. 悬浮窗：**默认关**，设置里开启。
> 3. 形态：**单个可拖圆钮**。
> 4. 清理：**两个目录（app-data + 项目目录）都统计、都清**。

---

## 1. 问题陈述

1. 截图/粘贴图片当前写入 `%APPDATA%\<app>\composer-images\`——隐形位置、无界增长、用户无法管理。
2. 截图流程必须先让 Hermes 主窗口获得焦点再点按钮；高频截图场景多一次窗口切换。
3. 没有任何清理入口。

## 2. 方案

### 2.1 截图目录配置（设置 → 新增"截图"区）

新增配置项（desktop 本地配置，存 config.yaml 或桌面 store——按现有桌面设置惯例选择）：

- `screenshots.dir_mode`: `app_data`（默认）| `project`（项目目录）
- 项目模式路径约定：`<当前工作区>/.hermes/screenshots/`

**关键决策（修正用户原始提议的默认值）**：默认**不**放项目目录——往仓库工作区写目录会产生 git status 噪声。项目模式开启时，自动把 `.hermes/screenshots/` 追加到该仓库的 `.git/info/exclude`（repo 本地排除，**不碰**用户 `.gitignore`），幂等、可重入。

项目模式的收益（如实呈现给用户）：截图随项目归档、会话中的 agent 后续可用文件路径复读该图。

### 2.2 截图悬浮窗（设置开关，默认关）

- 开启后显示一个 always-on-top 小圆钮（右下角，可拖动记忆位置）；点击 → 直接弹窗口选择器（复用 v0.18.8 的选择器+标注编辑器）。
- **必须处理**:
  - 浮窗自身（及其 label）从 `list_windows` 排除；
  - 触发"整个屏幕"截图前临时隐藏浮窗，截完恢复——否则浮窗会被拍进全屏图；
  - 主窗口关闭时浮窗随退（不孤儿）。
- 实现：Tauri 二级窗口（frameless + alwaysOnTop + skipTaskbar），创建走 `run_on_main_thread`（沿用 0.18.5 的 async 命令死锁教训）。

### 2.3 一键清理（设置 → 截图区）

- 显示当前截图目录的总大小与文件数（`app_data/composer-images` + 若项目模式开启则含项目目录）。
- [一键清理] 按钮：二次确认后删除内容（仅该目录内文件），回报释放空间。

## 3. 边界与约束

- 目录切换只影响**之后**的截图；存量文件留在原目录（清理按钮覆盖两个位置，避免"切换后清不掉旧文件"的困惑）。
- 项目模式且当前无工作区（detached 会话）→ 落回 app_data 并注明。
- 清理是**删除文件**操作：仅限受管目录、二次确认、不动任何其他路径。
- 附件引用的是文件路径——清理后，历史消息里的图片附件将 404。清理确认文案需写明这一点。

## 4. 测试计划

- vitest：目录解析（app_data/project/detached 回退）、git-exclude 幂等追加、清理确认流、浮窗开关状态。
- Rust：git-exclude 追加逻辑可抽纯函数做 cargo test；目录统计（大小/计数）同样可测。
- CDP e2e：设置区渲染、清理按钮生效（造测试文件→清理→计数归零）。

3. **悬浮窗形态**：单个可拖圆钮（推荐）vs 小工具条（截图+更多快捷入口）?
4. **清理范围**：两个目录都清（推荐）还是仅当前生效目录？
